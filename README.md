# 🎸 Telegram CMS Bot для Преподавателя Музыки

Информационный чат-бот с полноценной встроенной панелью администратора (CMS), разработанный для автоматизации маркетинга, презентации услуг и лидогенерации для частного преподавателя музыки (гитара, вокал, клавишные).

**🔗 Ссылка на демонстрационную версию бота:** [@Ваш_Тестовый_Бот](https://t.me//Demo_Music_Teacher_bot)*(работает в режиме Staging)*

---

## 🚀 Ключевой функционал

### 👤 Для пользователей (Учеников):
* **Интерактивное меню:** Удобная и быстрая навигация по разделам «О преподавателе», «Цены и абонементы» и подробному FAQ.
* **Лидогенерация:** Прямая интеграция с личным профилем преподавателя для оперативной связи и записи на пробный урок.
* **Мультимедиа:** Отображение актуальных медиа-материалов (главное фото профиля) и динамическое обновление описаний.

### 👑 Для администраторов (Преподавателя):
* **Встроенная CMS (No-Code изменение контента):** Возможность редактировать любые тексты меню, блоки цен и разделы FAQ прямо через чат Telegram в реальном времени, без изменения исходного кода программы и перезапуска сервера.
* **Динамическая замена медиа:** Команда `/edit_photo` позволяет обновить главное фото профиля на лету, просто отправив новую фотографию боту.
* **Отказоустойчивость (Reset):** Наличие команд моментального сброса любого текстового блока к первоначальным эталонным настройкам на случай ошибок ввода.

## 🛠 Архитектурные особенности и Стек технологий

Проект спроектирован с упором на модульность, отказоустойчивость и легкость деплоя:
* **Язык разработки:** `Python 3.11+`
* **Фреймворк:** `Aiogram 3` (асинхронная архитектура, использование `Router` для изоляции модулей и высокой масштабируемости).
* **Управление состояниями (FSM):** Потокобезопасное переключение контекстов администрирования через `FSMContext` (исключает конфликты при одновременной работе нескольких администраторов).
* **Авторизация и безопасность:** Валидация административных команд вынесена в кастомный переиспользуемый фильтр доступа (`BaseFilter`), проверяющий Telegram ID пользователя.
* **Хранение данных (Data Persistence):** Легковесная файловая база данных на базе JSON с автоматической синхронизацией на диск (`try...except`). За счет монтирования Docker Volumes данные гарантированно сохраняются при перезапуске или обновлении контейнера.
* **Конфигурация:** Чувствительные данные (API-токены) полностью изолированы от кодовой базы и управляются через переменные окружения (`.env`).
* **Тестирование (QA):** Бизнес-логика, фильтры и хранилище покрыты 26 асинхронными тестами (pytest, pytest-asyncio). Общее покрытие кода (Test Coverage) составляет **85%**

## 📦 Инструкция по локальному и серверному развертыванию

### Способ 1. Запуск через Docker (Рекомендуемый для Production)

Убедитесь, что у вас установлен Docker.

1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com
   cd имя_репозитория
   ```
2. Создайте файл конфигурации окружения `.env` в корне проекта:
   ```text
   TEACHER_BOT_TOKEN=1234567890:ABCdefGhIJKlmNoPQRsTUVwxyZ
   ```
3. Соберите Docker-образ:
   ```bash
   docker build -t music_teacher_img .
   ```
4. Запустите контейнер с изолированным хранением данных (Volume) и автоматическим рестартом:
   ```bash
   docker run -d \
     --name music_bot \
     --restart unless-stopped \
     --env-file .env \
     -v $(pwd)/data:/app/data \
     music_teacher_img
   ```
   *(Примечание: Убедитесь, что ваш `storage.py` сохраняет JSON-файл в папку `data`, чтобы работал бэкап данных на хост-систему).*

### Способ 2. Классический запуск в виртуальном окружении (для разработки)

1. Создайте и активируйте виртуальное окружение:
   ```bash
   python -m venv venv
   source venv/bin/activate  # Для Linux/macOS
   # venv\Scripts\activate   # Для Windows
   ```
2. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
3. Экспортируйте токен бота в переменные окружения и запустите проект:
   ```bash
   export TEACHER_BOT_TOKEN="ваш_токен"
   python main.py
   ```

## 🧪 Запуск тестов

Для запуска тестов и генерации отчета о покрытии кода выполните команду в виртуальном окружении:
```
python -m pytest --cov=. tests/
```
Если бот уже запущен в Docker-контейнере, тесты можно выполнить внутри него:
```
docker exec -it music_teacher_bot pytest -v
```
 
## 📁 Структура проекта

```text
├── tests/             # Автоматические тесты проекта (26 тестов)
├── config.py          # Глобальная конфигурация, ID администраторов, эталонные тексты

├── Dockerfile         # Инструкция сборки легковесного контейнера на базе python-slim
├── .dockerignore      # Исключение системного мусора (__pycache__, .env) из сборки
└── requirements.txt   # Зависимости проекта
```
